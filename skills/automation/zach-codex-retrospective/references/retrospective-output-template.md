# Retrospective Output Template

Output exactly these sections.

## 1. Retrospective Summary

- 3-6 bullets.
- Include both friction and strong successes.
- Tie each point to concrete sessions, commits, dates, or repo areas when
  available.

## 2. Proposed AGENTS.md Updates

Only include if changes pass `change-gates.md`.

For each proposal:

- Target file and exact location.
- Precise text to add or replace, preferably as a compact diff.
- One-sentence rationale tied to observed evidence.

## 3. Proposed New or Updated Tiny Skills

Maximum 0-2.

For each proposal:

- Suggested path.
- Complete `SKILL.md` content.
- Required README/symlink updates if the target repo enforces them.
- Why this deserves a separate skill file.

## 4. Evidence & Rationale

For every proposal above, list the concrete evidence that justifies it.

If the available history is incomplete, say what was available and avoid
overclaiming.

## 5. Application Recommendation

- Suggested order of applying changes.
- Verification commands.
- Whether another retrospective in 2-4 weeks is likely to be useful.

If no high-confidence improvements are found, say so plainly and stop after this
section.
